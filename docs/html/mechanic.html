Mechanic guide

Schema internals and the build

Everything needed to maintain the WARP schema and compile a database: what each file is, how the scripts work line by line where it matters, what the checks enforce, and where the sharp edges are. Assumes you've read the advanced guide for the concepts.

Compiling a full database

The Makefile builds the worked example. A real database is the same pipeline over many StatementSet files. Three constraints shape how you organize it:

1. Derivation is per file. derive_propositions.py takes one input and one output. Statements only share a proposition if they're in the same StatementSet. Two files with matching statements produce the same hash id (the key is deterministic) but separate proposition objects with separate derived_from_statements. To aggregate across sources, merge statement sets before deriving, or derive per file and union propositions by id afterwards.
2. References resolve only across the files you check together. check_statements.py builds its id index from the files on its command line. An assessment citing statements and propositions must be checked alongside the derived files that define them.
3. Assessments should cite stable ids. Derived proposition ids are SHA-1 hashes of the identity key, stable across runs but changed by every identity-rule version. Open-question ids never change. Assessments that cite derived ids need re-pointing after a rule bump.

A sequence that respects all three:

# 0. One-time per template change
linkml-validate -s src/warp/schema/warp_templates.yaml -C NodeTemplateCollection templates/node_templates.yaml
python scripts/gen_dosdp.py templates/node_templates.yaml patterns
for f in patterns/*_*.yaml; do python -m dosdp validate -i "$f" || exit 1; done

# 1. Nodes: expand_nodes takes any number of StatementSets and dedupes rows by node id
python scripts/expand_nodes.py templates/node_templates.yaml data/*.yaml \
  --owl project/nodes.ttl --tsv-dir patterns/data

# 2. Merge statement sets that should aggregate, then derive
python scripts/derive_propositions.py build/merged.yaml build/merged.derived.yaml

# 3. Shape validation: every file, including assessments
linkml-validate -s src/warp/schema/warp.yaml -C StatementSet build/merged.derived.yaml assessments/*.yaml

# 4. Semantic checks: everything that cross-references, in one call
python scripts/check_statements.py build/merged.derived.yaml assessments/*.yaml

# 5. Optional: OWL 2 EL check of the node classes
robot validate-profile --profile EL --input project/nodes.ttl --output build/el-report.txt

The merge step isn't implemented in the repository. A merge must concatenate every list slot of StatementSet (agents, nodes, node_definitions, each group's statements and propositions, assessments, study_results, documents), dedupe by id, and fail if one id maps to two different objects (the same rule check_statements.py applies within a file). Open questions must be carried through untouched so their ids survive.

Schema architecture

Import, don't fork

imports:
  - linkml:types
  - upstream/sepio_classes      # SEPIO Core IM, pinned
  - upstream/causalmosaic       # CAMO 0.8.x, pinned
default_prefix: warp            # https://w3id.org/ecoweaver/warp/
default_range: string

Upstream files are vendored unchanged. All EcoWeaver changes are made in warp.yaml by:

  • is_a: subclassing SEPIO classes (EcoStatement is_a Statement, …);
  • slot_usage: narrowing inherited slots (range, required, identifier, inlining);
  • attributes: adding class-local fields;
  • own class_uris in the warp: namespace, so profile classes aren't mistaken for SEPIO's.

Vendoring rather than URL imports is deliberate: LinkML URL imports aren't pinned, and an upstream change must never silently change what data means.

Specialize, then leave the generic field empty

Following SEPIO's advice for profiles, generic Coding fields are specialized as named, enum-typed attributes, and the generic field must stay empty (enforced by check_statements.py):

Inlining and references

Which objects are nested and which are referenced by id determines what linkml-validate can and can't check.

Inlined (nested objects)Referenced by id
Every StatementSet list; hasEvidenceLines; contributions; recordMetadata; care; predicate_qualifiers; comparator; context; temporal_extent; source_spans; fillers; dataItems; sourceDataSet subject/object (→ nodes); proposition; targetProposition; derived_from_statements; contributor; knowledge_holders; reportedIn; evidence_item_refs (plain uriorcurie)

linkml-validate doesn't verify that references resolve, and evidence_item_refs isn't range-typed at all (an item can be a statement, study result, document or dataset record). Referential integrity is entirely check_statements.py's job.

The type field on objects names the concrete class (CausalStatement, EcoEvidenceLine, …) and is how the validator picks the class for polymorphic ranges.

Predicate-group registry

Scripts discover groups from annotations, so adding one needs no code changes. A group is any class carrying warp_group:

CausalStatement:
  is_a: EcoStatement
  annotations:
    warp_group: causal                          # part of the identity key
    warp_statements_slot: causal_statements     # StatementSet list of statements
    warp_propositions_slot: causal_propositions # StatementSet list of propositions
    warp_proposition_class: CausalProposition   # written as `type` on derived propositions

load_groups(schema_path) in derive_propositions.py:

  1. Builds a SchemaView and iterates all_classes().
  2. Skips classes without their own warp_group annotation (annotations aren't inherited here, so a subclass of CausalStatement isn't a group unless annotated).
  3. Resolves induced_slot("predicate", cls).range. If it isn't an enum, exits: <cls>: predicate range X is not an enum.
  4. Collects each permissible value's rosetta_template annotation for rendering.
  5. Returns groups sorted by group name. check_statements.py imports this same function.

The registry doesn't verify that the named slots exist on StatementSet; a typo just means the group finds no statements. Check the derivation report lists your group with the counts you expect.

Derivation algorithm

derive_propositions.py IN OUT [--schema PATH]. RULE_VERSION = "warp-prop-identity/3".

Identity key and id

identity_key = "|".join([group, subject, predicate, object,
                         "negated" if negated else "affirmed", scope])
proposition_id = "warp:prop/" + sha1(identity_key).hexdigest()[:12]

Subject and object are compared as raw node id strings: no normalization, no reasoning. Two different node ids for the same OWL class are different propositions. Keep node ids canonical.

Per group

  1. Seed with open questions. For each existing proposition in the group's list: if status == open_question, set raised_as_question: true. Keep only propositions with raised_as_question; reset their key, rule version, derived_from_statements: [] and status: open_question. Every other existing proposition is discarded: derived propositions are rebuilt from scratch.
  2. Walk statements. If scope is missing, empty or unclear: remove proposition, remove targetProposition from its evidence lines, record it as skipped, continue.
  3. Compute the key. Look it up; if absent, create a proposition with the hash id, type = the group's proposition class, s/p/o, negated, scope, rendered propositionText.
  4. If the match is a raised question with no description yet: move its question text to description ("Raised as an open question: …") and replace propositionText with the rendered fact.
  5. Set status: asserted, key, rule version; append the statement id to derived_from_statements (no duplicates).
  6. Set the statement's proposition, and targetProposition on each of its own evidence lines.
  7. Write propositions sorted by id; drop the list if empty.

Rendering

text = rosetta_template.format(subject=node.name, object=node.name)
       # fallback: "{subject} <predicate with _ → space> {object}"
if negated: text = "it is not the case that " + text
prefix = {assertional: "In a particular case, ", contingent: "Sometimes, ",
          prototypical: "Typically, ", universal: "Always, "}[scope]
text = prefix + lowercase_first_char(text)  + "."

Node names are inserted verbatim, so a capitalized node name mid-sentence stays capitalized ("…prevents Population growth rate of…").

Output and guarantees

  • Writes # GENERATED by scripts/derive_propositions.py (warp-prop-identity/3). Do not edit propositions by hand. then yaml.safe_dump(sort_keys=False, width=100). Comments in the input are not preserved.
  • Report to stdout: per group, each proposition id, status, text and source statements. Skipped statements to stderr. Exit status is 0 even when statements are skipped.
  • Idempotent: running on its own output gives the same result. The example's derived file reproduces byte-for-byte.

Statement checks

check_statements.py FILE [FILE …] [--schema PATH]. Covers what SEPIO leaves to "additional tooling". Exit status 1 on any error.

How it indexes

walk_ids collects every object with a string id, at any depth, in every file: statements, propositions, agents, contributions, evidence lines, documents, study results, data items, datasets. All become resolvable reference targets. Within one file, an id seen twice must map to identical objects (so a dataset inlined under two study results is fine if the copies match). Across files, ids are unioned without comparison.

Warnings

  • A statement or assessment with no author contribution.
  • An annotated statement with no annotator in recordMetadata.contributions.

Assessments are checked with annotated=False: they may fill direction/strength, and don't need an annotator. Agents are looked up for the CARE rule only if they appear in some file's top-level agents list. Agent kinds of authors not in any file are treated as unknown (no CARE requirement), though the unresolved contributor reference is itself an error.

Grammar:

ClassExpression := (genus CURIE | var NAME)  AND  Restriction*
Restriction     := property CURIE  some  ClassExpression

That's EL: intersections and existential restrictions. Unions, negation, subClassOf-only patterns, data properties and list variables aren't supported; adding them means changing templates_lib.py and gen_dosdp.py together.

check_template (templates_lib.py)

Run by both generators. Raises TemplateError for: duplicate var names; a level with both or neither of genus/var; a genus, property or var range without a label in terms; a term used as the wrong kind; vars used but undeclared; vars declared but unused; {placeholders} in name/definition that aren't vars. Unknown prefixes fail in expand_curie.

gen_dosdp.py: template → DOSDP pattern

DOSDP keyFrom

Also writes patterns/prefixes.yaml (sorted). Errors per template are printed and the script exits 1 after processing the rest.

expand_nodes.py: node definitions → OWL + TSV

For each node_definitions entry, in every StatementSet given:

  1. Template must exist. Every declared var filled exactly once; no undeclared vars; filler CURIE prefix in allowed_prefixes; if the node has an entity_type, it must equal the template's camo_entity_type. Problems are collected, not fatal, until the end.
  2. Label and definition: name/definition filled with filler labels (falling back to CURIEs), whitespace collapsed.
  3. OWL: owl:Class with rdfs:label, IAO:0000115 definition, dcterms:conformsTo the pattern IRI, and owl:equivalentClass built recursively (intersection of head and owl:someValuesFrom restrictions). Every referenced class and property is declared, so the file is a standalone OWL 2 EL ontology.
  4. TSV row: defined_class, defined_class_label, then <var>, <var>_label per var. Rows are deduplicated by node across files and sorted.

It doesn't check that a filler is actually a subclass of the var's range: that needs the ontologies, and is left to ODK/ROBOT. Exits 1 listing every problem, so it's CI-safe.

Two routes, same axioms

Turtle from expand_nodes.py, or dosdp-tools generate on the patterns and fill tables (make owl-dosdp, or an ODK repo: copy patterns to src/patterns/dosdp-patterns/, TSVs to src/patterns/data/default/, set use_dosdps: TRUE). The logical axioms were confirmed identical with robot diff.

Generated artefacts and expected warnings

  • project/warp.schema.json: JSON Schema for the whole profile, including imported classes (~8k lines).
  • project/warp.owl.ttl: OWL rendering of the profile. Not yet grounded: SEPIO's LinkML has no class_uris or mappings to the SEPIO OWL ontology, and its default prefix is the placeholder https://example.org/sepio-model/.
  • linkml-lint warp.yaml: camelCase slot-name warnings come from upstream SEPIO and are expected (the Makefile ignores this lint's exit code). Anything else is yours.
  • gen-owl: "ambiguous attribute" warnings come from CAMO's CausalEdge defining fields as inline attributes; expected until CAMO promotes them to slots.

Extending WARP

Add a node template

Full guide: docs/node-templates.md. In short:

  1. Design the shape as a phrase with blanks, leaving out direction of change. Reuse an existing template if the logical shape matches.
  2. Add every fixed class and property to terms with its current OLS label (labels drift: RO:0000052 is now characteristic of); add new prefixes.
  3. Add the template entry. Keep allowed_prefixes tight. Use an id containing an underscore (see gotchas).
  4. make patterns, then fill it in a node_definitions entry and make nodes.

Released templates are frozen. Changing one's logical definition silently changes every node made with it. Make a new id and mark the old one deprecated.

Add a predicate group

Full guide: docs/predicate-groups.md. All edits in warp.yaml:

  • Predicate enum, each value with a meaning (checked in OLS) and a rosetta_template annotation
  • Qualifier class, avoiding SEPIO slot names (direction, strength, score, subject, predicate, object, qualifier)
  • Statement class: is_a: EcoStatement, own class_uri, the four warp_* annotations, subject/predicate/object constrained and required, negated with ifabsent: "false"
  • Proposition class: is_a: EcoProposition, same constraints
  • Two StatementSet lists, named exactly as in the annotations, inlined_as_list
  • Node templates for the subjects and objects
  • An example statement; make lint all passes; the derivation report lists the group; version bumped; README updated

Change the identity rule

  1. Edit identity_key() (and the module docstring) in derive_propositions.py.
  2. Bump RULE_VERSION. Every proposition records it.
  3. Re-derive everything. All derived ids change; open-question ids don't. Re-point assessments that cite derived ids.
  4. Record the change in the README's identity section and changelog.

Versioning and release

The profile version appears in several places that must move together:

  • version: in warp.yaml
  • StatementSet.profile_version ifabsent: string(0.5.0) in warp.yaml
  • profile_version in each example file
  • README status line and Changes section
  • RULE_VERSION, if identity changed
  • warp_templates.yaml version, if the template schema changed
  • make clean all, commit regenerated patterns/, project/ and *.derived.yaml

Gotchas

  • Template ids without an underscore aren't DOSDP-validated. make patterns loops over patterns/*_*.yaml (to skip prefixes.yaml), so a template id like population is generated but never validated.
  • Derivation drops comments from the input YAML. Keep annotator commentary in fields (description, original_text), not YAML comments, if it must survive.
  • Derivation drops hand-written asserted propositions silently.
  • Derivation is per file; see compiling a full database.
  • Node identity is string identity during derivation. Two node ids with equivalent OWL definitions still split propositions.
  • make clean deletes all of project/, including committed outputs, and all of patterns/*.yaml.
  • make check skips the raw statements file: it checks the derived file (a superset) and the assessment.
  • Duplicate-id comparison is per file only. The same id used for different objects in two files isn't detected.
  • The scripts/ directory must be importable: expand_nodes.py and gen_dosdp.py import templates_lib, and check_statements.py imports from derive_propositions. Running them by path (python scripts/x.py) handles this.
  • Mid-sentence capitals in rendered proposition text come straight from node names.
